# 画像与成果

只有用户明确选择 INSEQ 画像管理时，一份画像对应一个项目。聊天中的长期账号、产品、服务知识留在宿主，遵循[宿主知识](../references/host-knowledge.md)，不为记忆自动创建项目。使用 `inseq_list_projects` 查找、`inseq_list_items` 列出资料、`inseq_get_item` 读取正文；以用户选择为准，重名时在对话中区分，不能擅自合并项目。

只有明确要求创建画像时才调用 `inseq_create_project`，对应 100「画像构建」（`skill-profile-builder`）。初始收取名称、渠道和账号主页链接，可以有多个渠道；同时简短询问是否补充产品、服务或账号经营资料，允许暂不补充。已经提供或选择过的信息直接沿用，补充资料仅供本次画像任务使用，长期知识由宿主管理，不自动写入云端知识库。

提交后按原任务继续处理，完成必要的真实媒体读取并自动保存；不把空项目当作已完成画像，不设置二次确认或再次保存步骤。来源不足说明实际缺项，保护已有资料与人工修改。用户明确选择“暂无账号，手动建立”时才使用对应手动模式。

新建画像时省略 `project_id` 和 `id`，由服务端生成；这两个字段只用于复用本人已有项目，不能填随机 UUID。`PROJECT_NOT_FOUND` 时核对是否误传已有项目编号，不通过换主页或反复切换 manual 重试。

普通主页诊断走 11，不能自动进入 100。原文提取、热点研究和不使用画像的改写不要求先建项目。账号级任务回执中的 `project_id` 是后续查询、素材与成果的存储编号，不表示新建了可见画像，不让用户另建项目来替换它。

成果更新前读取最新版本，按服务返回的版本号保存；冲突时重新读取并合并，不盲目覆盖。停止和恢复使用原任务记录，主动停止不能自动恢复。完成后在当前对话交付全文、附件或实际文件链接，保存只是后台记录，不是额外查看步骤。
