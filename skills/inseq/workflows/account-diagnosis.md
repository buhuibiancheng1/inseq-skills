# 对标账号分析

“分析这个账号”“看看这个主页有什么问题”直接调用 `inseq_analyze_account`，对应 11「对标账号分析」（`skill-account-diagnosis`）。使用用户已提供的主页链接和渠道，不以单条作品代替整个账号，不要求用户填写可由服务取得的账号事实。

明确当前项目时报告归该项目，否则保留为账号分析记录。不自动创建画像；只有用户明确要求创建画像才进入[画像与成果](project-management.md)。

按服务真实回执持续查询同一任务，直至本次作品、评论、原片与转写全部准备结束。准备期间只给简短文字进度，不打开可视化窗口、不先交一份报告，也不以“需要的话可以继续等待”结束已授权任务。出现真实阻塞或用户主动停止时如实说明并保留原任务，不编造完成。

准备结束后实际读取全部可用作品声画和评论，记录作品、时间及覆盖范围，再用 `inseq_complete_media_work` 保存报告。只有成功保存完整分析，才能作为完整报告交付并结束任务；`partial` 不是成功完成。转写文字不等于实际读取画面；宿主缺少读取能力时说明具体阻塞，不用元数据报告代替声画诊断。

抖音优先选择主页热门候选中的高点赞作品，按实际点赞数从高到低选取；如只覆盖部分候选，说明实际范围，不称全账号历史最高赞。视频号、小红书保持默认选取方式。

抖音按账号作品总量分档：20 条以内采样最多 5 条作品、50 条一级评论；21–50 条最多 10 条作品、100 条一级评论；50 条以上最多 20 条作品、200 条一级评论。作品或评论不足时使用实际数量，一级评论跨作品去重累计；不能把第一页条数当作账号总量。视频号、小红书保持服务各自默认值。账号关注、粉丝、获赞和作品总数使用主页统计；采样作品评论合计和已采集评论样本数明确标注范围，不作为全账号评论总数。

按[结果卡片](../references/result-cards.md)交付。仅当 `delivery.card_available=true` 时调用一次 `inseq_preview_results`，展示本次 `visualization` 完整账号资料卡：作者、头像、简介、已返回的账号统计、作品封面、互动数据、原作链接和视频预览。支持 MCP Apps 时直接渲染；否则使用宿主实际具备的交互网页或应用能力呈现返回的 `visualization.html`。同一任务已展示卡片，不因查询进度或保存报告再次打开。仅保存 HTML 文件不等于显示交互卡片。不要只用 Markdown 表格替代资料卡，也不要把独立示例测试当成本次真实账号结果。缺失字段及标签直接隐藏，真实 0 保留。

宿主确实没有上述展示能力时如实说明，并在当前对话交付可用图片和本次原片只读链接。不要声称卡片已经显示，不让用户前往 INSEQ 项目查看。资料卡展示和视频可预览不代表 Agent 已实际观看声画。

单篇转写未完成时保留已有完整原文和部分片段，说明实际覆盖范围；不擅自称为超时，不重复采集或新建转写任务。报告区分实际观察与建议；收藏/点赞比不能称收藏率，咨询评论不能证明成交或获客链路通畅。

报告在当前对话完整交付。区分账号事实、内容表现和评论样本观察，结论保留来源，不从公开互动声称掌握完整粉丝人群或账号经营目标。用户续改时使用已保存报告，不重复采集同一任务。
